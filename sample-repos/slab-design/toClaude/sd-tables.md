# slab-design 데이터베이스 테이블 정의

각 테이블당 **설명 bullet 리스트만** 적으면 됩니다. 컬럼명·타입·PK/FK 는 Claude 가 도메인 컨벤션 기반으로 자동 생성.

## 작성 가이드

- 항목당 한 줄: `- 설명 (PK 또는 FK 표시 — 있으면)`
- PK/FK 표시 예: `(PK)`, `(FK→ORDER_OS)`, `(PK, FK→ORDER_OS)` — 빠뜨리면 Claude 가 추정 후 확인 요청
- 미리 적어둔 bullet 은 **알고리즘 doc 기반 추정** — 그대로 OK 면 두고, 빠진 항목 추가, 불필요하면 삭제
- 한 테이블 끝나면 `STATUS: TODO` → `STATUS: DONE` 변경 후 채팅으로 알려주세요
- "이 컬럼은 정확히 어떻게 부르나" 같은 명명 질문은 Claude 에게 따로 물어보셔도 됨

## 전역 규칙 (사용자 결정사항)

- **회사코드 + 소코드**: 모든 테이블의 PK 복합키 일부. 각 테이블 bullet 에 매번 적지 않아도 됨 — JPO 생성 시 자동 포함
  - ORDER 4종 PK: `(회사코드, 소코드, 주문번호)`
  - 기준 마스터 PK: `(회사코드, 소코드, 룩업키…)`
  - 결과/이력 PK: `(회사코드, 소코드, ID)`
  - 모든 FK→ORDER 도 복합키 매칭 `(회사코드, 소코드, 주문번호)` 로 자동 처리

- **레거시 비표준화 전략 (데모 핵심 가치)**: 같은 도메인 개념이지만 테이블마다 컬럼명·타입이 다른 패턴을 **의도적으로 보존**. 도구의 온톨로지 매핑이 푸는 정확히 그 영역.
  - 품명/품종/품종코드 → 모두 동일 의미, 컬럼명만 다름
    - `PRODUCT_TYPE_CD VARCHAR2(4)` (ORDER_OM, CAST_SPEC, HR_SPEC, EDGING_GROUP)
    - `PRODUCT_NAME_CD VARCHAR2(3)` (CUSTOMER_STD)
    - `PROD_KIND_CD VARCHAR2(4)` (SD_PRODUCTIVITY_STD)
  - 열연공장코드/열연코드 → 동일, 다른 이름
    - `HR_PLANT_CD CHAR(1)` (HR_SPEC)
    - `HR_CD CHAR(1)` (HR_MAX_WGT, HR_MIN_WGT)
  - 다른 비표준화 패턴은 알고리즘 시연 단계에서 추가 가능

# 작성 후 흐름

각 Step 끝나면 `STATUS: DONE` 표시 + 채팅으로 알려주세요. Claude 가:
1. bullet 들을 컬럼명·타입·PK/FK 가 채워진 표로 변환 (이 파일 안에)
2. 변환된 표를 사용자에게 보여주고 confirm 받음
3. confirm 후 해당 P2 단계 코드 (JPO·Entity·Logic·Repository) 작성

진행 순서:
1. **Step 1** 완료 → P2.0 SDOrder + P2.1 Phase 1
2. **Step 2** 완료 → P2.0 std + P2.2 알고리즘 steps 1~3
3. **Step 3** 완료 → P2.2 steps 5~6
4. **Step 4** 완료 → P2.4 결과/이력
