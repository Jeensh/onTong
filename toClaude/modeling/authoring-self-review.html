✓ 비용 budget 안에 있음

✓ 영구 저장 작동

  • 기존 onTong 의 ontology DB schema 재사용 — 별도 mock 없음

B. UX 개선 (작지만 임팩트 ↑)

  • Streaming 미구현 ❌ — 매 turn 30~40s 동안 사용자는 spinner 만 봄. 대안: SSE 글자 단위 stream → "AI 가 생각 중" 체감 ↓
  • 진행률 표시 부재 — turn 1/8, 2/8 … 같은 phase indicator 없음
  • 토스트 없음 — confirmed 등 큰 이벤트가 chat 메시지로만 표시됨
  • cost breakdown 없음 — 누적 USD 만, capability 별 분류 안 보임
  • option card hover detail 부족 — pros/cons 다 inline. hover 시 expand 같은 거 없음
  • archive markdown 너무 김 — collapsible 또는 short summary + click-to-expand 필요
  • error retry 없음 — 갭에 빨간 banner, retry 버튼 없음. 사용자가 turn 다시 trigger 해야 함

C. 기능 추가 (필수에 가까운)

  • Session 재개 없음 — 페이지 새로고침 시 frontend store reset → backend 결정 로그는 살아있지만 frontend 가 끊김
  • 이전 session list view 없음 — DB 에 6 sessions 누적되지만 UI 에서 못 봄
  • Repo 선택 없음 — repo_id "smoke-slab" 하드코딩
  • cap 7 (pattern_checker) 미구현 — 옵션 제시 전 sibling entity 와 일관성 검사. 두 번째 entity 만들 때부터 가치 ↑
  • cap 10 (next_step) 미구현 — confirm 후 "다음 어느 entity 만들까?" 추천
  • "세분화" 명령 — 사용자가 chat 으로 "더 잘게 쪼개줘" 같은 명시 명령 못함
  • 갭 모달 없음 — Round 5 Step 14 §C 의 "비대칭 발견 시 별도 모달" 패턴 미구현

§6. 우선순위 제안 (4 wave)

Wave 1 — 즉시 (사용자 만족감 ↑↑, 작은 작업)

  • Streaming 응답 (SSE) — 이거 하나로 만족감 80→90% (Step 15 권장)
  • 진행률 표시 — "turn 5/8 옵션 제시 중..." 같은 phase indicator
  • cost breakdown — 우측 패널에 capability 별 USD 분리
  • error retry 버튼 — 실패 시 "다시 시도" 한 번 클릭

Wave 2 — 다음 entity 만들 때 필수 (Pattern reuse)

  • cap 7 (pattern_checker) — 두 번째 entity 부터 일관성 보장
  • Pattern library 등록 — 옵션 채택 시 "Plant + Constraint Composition" 같은 패턴 자동 저장
  • option_proposer 가 패턴 재사용 — 빈 list → 등록된 패턴 list 전달
  • cap 10 (next_step) — confirm 후 "다음 어떤 entity?" 추천

Wave 3 — 실용성 (multi-entity / multi-session)

  • File picker — repo_import 와 연동. 사용자가 JPO 선택 가능
  • Session 재개 — URL ?session_id=… 추가, frontend store hydrate
  • 이전 session list view — sidebar 에 "내 인터뷰" 목록
  • Confirm 후 graph 자동 전환 — entity persist 직후 🌐 Graph 모드로 + focus
  • archive markdown collapsible — 우측 length 부담 ↓

Wave 4 — 협업·고도화 (큰 작업)

  • Multi-operator branch/merge (M-2) — Round 5 결정 사항 구현
  • Live graph preview (dagre) — 카드 list → 실제 그래프 시각화
  • Gap Inspector inline 통합
  • archive history 검색
  • 인증/권한 통합

§7. 사용자 측 관찰 영역 (제가 모르는 것)

AI 자체 검토는 implementation 관점. 사용자가 직접 cycle 돌리며 본 것 중 위 list 에 없을 수 있는 것:
  • 특정 turn 의 응답 quality 가 기대보다 낮음 (LLM output 자체)
  • UI 의 시각적 어색함 (색상, 간격, 글자 크기, 한국어 wrapping)
  • 흐름 자체의 어색함 (어느 buttom 다음 어느 button 누를지 직관 ↓)
  • 도메인 정확성 (Round 5 결정과 다른 결정 도출됨)
  • 새 세션 시작이 강제되는 게 부담 (이전 세션 이어서 가고 싶음)
