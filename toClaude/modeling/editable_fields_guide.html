편집 가능 필드 가이드 — Modeling Section

5-ii Stage 1/2/3 어포던스 — 어떤 필드가 어떻게 편집되는지 한 눈에

5-ii (편집 어포던스) 단계 요약

Stage 1 — Confirm Toggle. 우상단 ConfirmToggle로 draft ↔ confirmed 전환만. 필드 본체는 안 건드림. 팀 동의 도장을 찍는 단계. (Term/Action/BR/Anchor)

Stage 2 — Inline Edit. 디테일 패널에서 ✏️ 아이콘 hover → 클릭 → 그 자리에서 편집. 단일 field 단위. 4가지 primitive (InlineEditText, InlineEditTextArea, InlineEditList, InlineEditSelect) 가 PATCH endpoint 1번 호출. 실수 정정 / 한 글자 수정용.

Stage 3 — Authoring Bridge. entity 신규 작성, 다중 field 동시 갱신, 코드↔온톨로지 연결 변경 등 대량 변경은 LLM 기반 Authoring 모드로. 디테일 패널 하단의 보라색 “✏️ Authoring 모드로” 버튼이 brigde.

각 entity 의 코드(파서 산출물)·구조 메타(verification_level, FQN) 같은 derived/structural field 는 절대 직접 수정 ❌ — Java 재파싱 또는 confirm toggle 로만 변경.

🟢 Inline Edit (Stage 2) 디테일 패널에서 ✏️ 클릭 → 그 자리에서 편집 → PATCH 1회
🔵 Confirm Toggle (Stage 1) draft ↔ confirmed 전환만. 본체 데이터는 변경 X
🟣 Authoring (Stage 3) LLM 기반 대량 변경 — 별도 Authoring 모드 진입 필요
⚪ Read-only 파서 산출물/derived/구조 — UI 에서 편집 불가
