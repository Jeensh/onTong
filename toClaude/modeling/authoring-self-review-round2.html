✏️ Authoring AI — 사용자 피드백 (1.5/5) 분석 + Round 2 토론

2026-05-05 · Round 5 인터뷰 form 패턴 그대로 — 질문 별 textarea
피드백 핵심 (사용자 직접 인용)
"답변 퀄리티가 부족한 느낌. 맥락을 어디까지 들고 있는지, 너랑 나랑 할 때는 내가 너의 질문이 이상하면 새로운 내용을 알려주면서 새롭게 검토/리프레시 하는 흐름이 좋았는데 그 부분이 약함."
"UI가 뭔가 가독성이 부족한 부분, md 뷰가 적용 안되는 글, 필요없는 섹션 사이징 및 아예 화면 칸에서 일시적으로 없애는 UI 등이 필요."
"질문을 한번에 여러개 답해야 하는데, 지금처럼 질문 별로 대답을 할 수 있는 구조가 좋은 것 같아."
"버튼 등 UI 가 좀 어색하고 구식의 느낌이 있어."
"지금 한거는 뭔가 너가 이걸 위해서 미리 준비해서 한 느낌이야. 내가 뭘 알려주기 전에 너무 많은 걸 알고 물어보는 느낌?"

자체 진단 — 5 가지 본질적 문제

  1. P1. "너무 많이 알고 물어보는 느낌" — 가설이 과하게 specific. confidence calibration 부재.
  2. P2. 맥락 정정 + 리프레시 흐름 부재 — backward / refresh 없음. step-by-step 단방향만.
  3. P3. 질문별 답변 구조 부재 — Round 5 form 패턴 잃음. 한 textarea 에 몰아넣음.
  4. P4. UI 가독성 / Markdown 미렌더링 — archive raw text. preview 섹션 항상 보임.
  5. P5. 버튼·디자인 어색 — 구식 느낌. spacing / typography / micro-interaction.

→ P1, P2 가 LLM behavior 의 본질적 문제. P3, P4, P5 는 UI 작업.

P1. "너무 많이 알고 물어보는 느낌"

진단

현재 hypothesis prompt 가 "코드 + 한국어 주석 모두 분석 → 도메인 entity 가설" 을 만들도록 강하게 push. 결과: 한국어 주석 ("열연설비사양기준") 을 그대로 활용해서 즉시 "열연공장" 같은 정답을 dump → 사용자에게 "왜 이렇게 잘 알지?" 위화감.

Round 5 의 자연스러움은 AI 가 모르는 척 시작 했기 때문. "이건 ... 같은데, 맞나요?" 라는 humble 자세에서 사용자가 가르치며 점진적으로 정확해짐.

옵션 비교

옵션접근장단
P1-A Hypothesis prompt 를 "humble" 모드로 — Korean comment 를 직접 인용하지 말고 "이건 X 같은데..." 형식 적은 변경 / 효과 작을 수도
★ P1-B Hypothesis 를 2-stage 로 분리: stage 1 "raw extraction 만 (가설 X)" / stage 2 "사용자가 이게 무엇 같냐고 물어볼 때만 가설" 사용자 주도성 ↑↑ / 클릭 1회 추가
P1-C Hypothesis 의 confidence 를 강하게 calibrate — 한국어 주석 있으면 0.6 max, 없으면 0.3 max. UI 에서 confidence < 0.5 면 "추측이 약합니다" 표시 UI 시그널 ↑ / behavior 자체는 같음
P1-D Hypothesis 자체 폐기 — 코드 추출만 보여주고 사용자가 "이건 뭐 같지?" 직접 짚음 가장 humble / 너무 minimal 가능

P2. 맥락 정정 + 리프레시 흐름 부재 (가장 본질적)

진단 — Round 5 패턴 vs 현재
Round 5 (사용자가 가르치며 정정):
  step 4 인터뷰 → 사용자: "EDGING 은 깎는 거야"
   ↓
  step 5 (가설 자동 정정) → 사용자가 새 답변
   ↓
  step 9 옵션 → 정정된 가설 위에 옵션 제시
   ↓
  step 10 비대칭 발견 → 다시 가설 재검토 (별도 step)

현재 (단방향):
  ① 코드 → ② 가설 (한 번 set) → ③ 인터뷰 → ④ 답변 → ⑤ 옵션 (가설 그대로)
  사용자가 답변에서 가설 뒤집어도 옵션은 처음 가설 기준으로 제시
  back 흐름 없음

옵션 비교

옵션접근장단
P2-A cap 4 (answer absorber) 가 contradicts_my_guess 발견 시 cap 2 (hypothesis) 자동 재호출 → 새 가설로 cap 6 (options) 진행 매끄러움 ↑ / 비용 +$0.16 (Opus 추가)
★ P2-B "refresh 버튼" 명시적 — 인터뷰 답변 후 우측 preview 의 가설 카드에 "이 답변으로 가설 다시 보기" 버튼. 클릭 시 cap 2 재호출 + 옵션 cleared 사용자 주도 / 1 클릭 / 비용 명시적
P2-C "실시간 가설 갱신" — answer 가 들어올 때마다 우측 preview 의 가설 카드를 자동 update (LLM 호출 없이 contradicted fields 만 strikethrough) 비용 0 / 미묘한 표현
P2-D chat 명령으로 "다시 검토해줘" 입력 → 임의 시점에 cap 2 재호출. Round 5 의 "세분화" 명령 패턴 유연 / 사용자가 명령 인지해야 함

→ B + C 조합도 가능. preview 자동 갱신 (C) + 명시 refresh 버튼 (B).

P3. 질문별 답변 구조 (사용자가 명시적으로 선호)

진단

현재 InterviewView 는 5-7 Q list 를 보여주고 사용자가 한 textarea 에 자유서술. cap 4 (answer absorber) 가 LLM 으로 그걸 분해. Round 5 의 form 패턴 (Q 별 textarea + my_guess + placeholder) 잃음.

사용자: "질문을 한번에 여러개 답해야 하는데, 지금처럼 질문 별로 대답을 할 수 있는 구조가 좋은 것 같아."

옵션 비교

옵션접근장단
★ P3-A Q 별 별개 textarea — Round 5 form 그대로. 각 Q 마다 my_guess + placeholder + skip 버튼. cap 4 (answer absorber) 의 LLM 호출 폐기 (이미 구조화돼서 들어옴) UX 가 Round 5 와 동일 / cap 4 LLM 비용 0 절감 / answer_absorber 코드 삭제 필요
P3-B 현재 single textarea + Q 별 textarea 둘 다 — 사용자 선택 유연 / 복잡
P3-C Q 별 textarea + 마지막에 "추가 의견" 단일 freeform 영역 structured + 자유 / Round 5 form 그대로

→ A 또는 C. C 가 Round 5 form 과 정확히 일치.

P4. UI 가독성 — Markdown 미렌더링 + 섹션 토글

P4-1. archive markdown

현재

우측 preview "Archive (markdown)" 섹션이 raw text 그대로 표시 (<pre> tag 안에). Markdown 헤더, 표, 강조 등 안 보임.

옵션접근
★ P4-1-A react-markdown + remark-gfm 도입 — markdown 렌더링. github-flavored.
P4-1-B archive 를 markdown 대신 HTML 직접 생성 — backend 에서 직접 HTML 출력

P4-2. 섹션 토글 (사용자 명시적 요청)

현재 vs 제안

현재 우측 preview 의 5 섹션 (세션/가설/채택옵션/엔티티/갭/archive) 모두 항상 표시 → 스크롤 부담.

사용자: "필요없는 섹션 사이징 및 아예 화면 칸에서 일시적으로 없애는 UI 등이 필요해 보여."

옵션접근
★ P4-2-A 각 섹션 collapsible (HTML <details> 또는 shadcn Accordion) — 기본 expanded, 클릭 시 접기
P4-2-B 섹션 별 닫기 버튼 (X) — 한 번 닫으면 안 보임. 다시 열려면 toolbar 의 "섹션 추가"
P4-2-C tabs 로 — 섹션 5개를 tab 으로 (한 번에 1개만 표시)

P5. 버튼·디자인 — "구식 느낌"

진단

현재 toolbar = 8 버튼 일렬 (① ~ ✓). 모두 같은 outline button. spacing/typography 통일성 부족. 진행상태 visual feedback 없음.

옵션 비교

옵션접근
P5-A shadcn 의 다른 component 활용 — Card / Badge / Progress / Stepper 등을 toolbar 대신 사용
★ P5-B Stepper UI — toolbar 대신 horizontal stepper (① → ② → ③ → ...). 현재 단계 highlighted, 완료 단계 ✓, 다음 단계 클릭 가능. 자동 진행 시 spinner
P5-C 버튼 통합 — "다음 단계 자동 진행" 버튼 한 개. 시스템이 알아서 chain. 사용자는 답변/선택만
P5-D 큰 디자인 시스템 작업 — Tailwind palette 다듬기, micro-interaction (hover/active animation), badge typography 등
