D.1 — 인계 onboarding doc (시뮬 에이전트 구현자 entry point)

진행 중 다음 개발자가 가장 먼저 읽을 문서

① 30초 요약 (TL;DR)

★ 한 화면 핵심

onTong = 레거시 Java SCM 시스템을 ontology + 코드 매핑으로 표현 → ChangeSpec 입력 → Python sandbox 시뮬 → diff 출력하는 도구.

당신의 역할: 본 ontology 와 매핑을 이용해 시뮬레이션 에이전트 구현. 입력 = ChangeSpec (Action FQN + atomic 값 변경). 출력 = SimResult (변경 전후 도메인 결과 diff).

입력 자료: 178 row ontology + 36 design-gaps + 41 Action 의 코드 위치 (realizes) + 17 BR + 4 sub-domain.

먼저 읽을 5 문서: ① 본 D.1 (onboarding) → ② D.2 (Ontology API) → ③ D.3 (ChangeSpec/SimResult schema) → ④ D.4 (Runner interface) → ⑤ design-gaps-and-questions.md (Phase E 미해결 36 항목).

② 도메인 primer (철강 SCM 슬랩 설계)

  • 슬랩 설계 (slab-design): 고객 주문 → 21-step Algorithm → 슬랩 (반제품) 사이즈 결정. 슬랩 = 연주(SM) → 열연(HR) → 냉연(CR) ... 8 공정 통과.
  • 21-step Algorithm: Phase 1 (5 Validator + 제품 분류 + 활성공정 폭 + 비중 + 누적실수율) + Phase 2 (one-shot 1~7 + A-a 루프 8~15 + final 16~19 + save 20 + history 21).
  • 핵심 entity: Order (4 sub Jpo) → SDSlabEntity (in-memory 작업) → SLAB_RESULT (DB 저장, 매수만큼 row 복제).
  • 표준 데이터 (lookup): HrSpec/CastSpec (설비 제약) / EdgingSpec/EdgingGroup (폭 변환) / HrMin·MaxWgt (단중) / CustomerStd (고객 제한) / ProductivityStd (실수율).
  • 운영 이슈 history 7건: P-2018-0098/0237/0721 + P-2019-0445 + P-2020-0411 + 2017 회의 + 정XX 2018-12-04. BR.operational_history 에 매핑.
  • drama DNA: 의도적 messy 패턴 — 동일 도메인 컬럼 다른 이름 (PRODUCT_NAME_CD vs PROD_KIND_CD vs PRODUCT_TYPE_CD), commented-out 레거시 fallback, javadoc 갭, hardcoded 매핑 등. 시뮬 시나리오의 가치 입증 영역.
