④ 온톨로지 그래프 — Top-down 도메인 흐름 + Subgraph 탐색 NEW v4

4
사이드바 「온톨로지 그래프」
탭 #4
v4 의 가장 큰 변경 — 평면 노드 폐기, Top-down 도메인 흐름
처음 진입 시 9 단계 카테고리 카드가 가로 흐름으로 표시: 주문 정보 → 화학 성분 → Slab 사양 → 공정 설비 → 주조·열연 사양 → 공정 매칭 → 설계 기준 → 일정·마감 → 상태·진도

카드는 viewport 에 맞춰 자동 줄바꿈 (4-4-1 또는 5-4 등). 짤림 0.

탐색 흐름

  1. 카테고리 카드 클릭 → 그 단계의 BusinessTerm 들이 펼쳐짐
  2. Term 클릭 → 그 노드 중심 1~3 hop subgraph 시각화 (xyflow + dagre LR)
  3. 노드 더블클릭 → 그 노드를 새 focus 로 (탐색 확장)
  4. focus picker (상단 칩) — 직접 검색해서 특정 term 시작점 선택

우측 detail 패널

  • 선택 노드의 연결 관계 (governs / part_of / related_to)
  • 매핑된 코드 위치 리스트 — confirmed ConceptBinding 자동 노출
  • 새 관계 추가 (term ↔ term / term ↔ rule)
💡 5000+ class 가정 — 항상 ~80 노드 cap. truncated 시 「깊이 3 → 2」 토글 권장.

⑥ 매핑 상태 — 코드 변경 후 깨진 매핑 자동 진단 NEW v4

6
사이드바 「🛡️ 매핑 상태」
탭 #6 (신규)
왜 만들어졌나 — Phase 1 silent corruption 차단
자바 코드를 리네임하면 (예: productTypeCd → productKindCd) 기존 confirmed binding 199개 중 일부가 존재하지 않는 위치를 가리키게 됨. 시뮬레이션 결과가 거짓이 됨. 사용자가 모르는 사이에.

이 탭은 코드 변경 → re-index → stale binding 자동 감지 → 새 위치 1-click rematch 까지 닫힌 루프.

화면 구성

  1. 매핑 건강도 막대 — 100% (emerald) / 70~95% (amber) / <70% (red). healthy/stale/total grid
  2. 마지막 재파싱 diff — +N -M + 추가/삭제 fqn detail
  3. 「재파싱 + 진단」 CTA (blue-600) — 12-analyzer 재실행 + sweep + diff 일괄 (slab demo 약 2초)
  4. 깨진 매핑 (N) 카드
    • term + 존재하지 않는 위치 (red highlight)
    • 새 위치 추천 — alias 정규화 (camel ↔ snake) + 단순 이름 + 부모 보존 3 tier
    • 각 후보: confidence (95% emerald / 70% amber / 40% slate) + 「적용」 1-click

비파괴 원칙

자동으로 binding 을 갱신하지 않습니다. 운영자가 「적용」 클릭해야 새 binding 이 confirmed + 옛 binding 이 rejected 됩니다 (audit log 자동 기록).

API (CLI 사용도 가능)

GET  /api/modeling/repos/{repo_id}/stale-bindings
POST /api/modeling/repos/{repo_id}/reindex
POST /api/modeling/bindings/{proposal_id}/rematch

⑦ 시뮬레이션 — Java→한국어 Python 변환 + Sandbox

7
Workbench R 「🔬 시뮬」 → 「+ 새 시뮬레이션」
bottom drawer

3-step wizard

  1. 변경 정의 — kind: method_body / anchor_value / rule_severity / rule_statement / term_binding. multi-method 도 가능 (related_methods up to 5)
  2. Sandbox 실행 — Claude 가 Java 본문을 한국어 변수명 Python 으로 변환 (예: slabWgt → 슬랩단중) → RestrictedPython sandbox 에서 실행 (NetworkPolicy + MemoryLimit). SyntheticInputGenerator 가 자동 input case 생성.
  3. Diff 검토 + Apply — before/after mutation diff (예: finalLengthLow: 8000 → 0.34 (-99.99%)) + 영향받는 BusinessRule 매칭 + severity (regression / minor / major). 「Apply」 → Java patch draft + 「GitHub PR 만들기」

시뮬레이션 기록 (history)

  • R 「🔬 시뮬」 탭 안 「📋 시뮬레이션 기록」 — 이전 spec 들 status badge + kind + description
  • 「↻ 다시 실행」 — cache hit 으로 즉시
