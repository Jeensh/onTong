3. Skeptic 의 11 Mandate — Round 2 합성이 답해야 할 것

Skeptic 은 design proposal 하지 않음. 대신 합성 전 반드시 답해야 할 빈틈 11종 catalog. 각 mandate 에 종합 설계의 응답을 inline.

M1. Name the second system — concrete non-v2 reference (language / framework / scale / pattern). 모든 system-agnostic claim test 됨
응답: Architect (A1) 의 hypothetical "bank-credit" (SpringBoot loan scoring + MyBatis + Reactor + CreditScoreException) 를 spec 의 reference 로 명시. 실제 onboarding 은 사용자 선정 후 별도 세션 — 단 framework 설계 자체는 bank-credit 의 plugin shape (7 artifact + 1 ontology) 으로 검증된 형태
M2. Recommendation scope decision tree — UC4 의 explicit scope: column add / + downstream code / multi-table refactor / full migration
응답: 3 sub-engine 직렬 (Schema → Code → Ontology) + 사용자 turn 단위 scope 선택. Default = "column add + downstream code stub + ontology delta". 다중 alternative (α: column / β: 새 table) 제시
M3. Determinism boundary — artifact provenance: deterministic vs LLM-derived; prompt+input hash for cache
응답: manifest.yaml per proposal — model_version + prompt_hash + ontology_revision + seed. Verification artifact 는 ontology_revision 만 의존 (fully deterministic). Recommendation artifact 는 manifest 4-tuple 의존 (동일 환경 reproducibility)
M4. Schema Layer migration plan — 새 5+ table 의 추가, audit_log / realizations / composition_edges 호환, migration + backout
응답: Additive only — 기존 17 table 의 row 미수정. CREATE TABLE 5 (schema_tables/columns/foreign_keys/indexes/constraints) + schema_code_map + ontology_revisions/proposals/verification_runs 3. Backout = drop the new tables (additive 이므로 zero-impact rollback). Seed 는 JPA annotation 자동 + 사용자 confirm
M5. Two-engine sync protocol — when Recommendation modifies ontology, conflict resolution, audit trail for LLM-derived state, versioning across 5 axes
응답: Integrator (transactional, ~200 LOC) 가 ontology mutation 의 단일 channel. Proposal lifecycle (draft → analyzing → ready → reviewed → accepted | rejected | stale). base_revision pin → 동시 proposal 중 first-apply wins, 나머지 STALE_PROPOSAL
M6. Layer 2 scaling test — 5K-8K method synthetic load
응답: AST visitor + role-based scope routing은 method 당 ~5ms 추정. 5K method ≈ 25s synthesis cold. Incremental synthesis (변경 file 만) 기본. Performance budget = 60s cold / 5s incremental
M7. Recommendation context retrieval — ontology 전체가 prompt 에 안 들어감 (5K+ class system). RAG 명시
응답: FTS5 인덱스 (BusinessTerm.synonyms + Action.name_ko + Method/Class fqn) → query 매칭 typed JSON 으로 top-N=20 + 2-hop graph 확장. Token budget 5-15K per call. v2 (985 method) 와 100K class system 동일 mechanism
M8. User trust mechanism — wrong recommendation detection: review UI, validation steps, "fixture-must-be-added-before-approve" rule
응답: Recommendation 의 output 에 항상 verification result 첨부 (regression S1-S5 + forward S6 expected). Forward fixture 의 expected output 은 사용자가 직접 작성 — LLM 자기 채점 차단. Apply 전 user-review gate (modeling UI 의 confirm queue 패턴 재사용)
M9. Onboarding cost honesty — per-new-system cost (mechanism vs curation), v2 ≥ 50h 와 비교
응답: Skeptic 의 실측 (medium Java ~100-150h / first non-Java ~200-400h+150h) 을 그대로 수용. ADR-002 의 "near-zero per-system cost" 가정은 잘못 — curation 이 dominant. Plugin scaffolding 만 reusable. 사용자에게 명시적 비용 surface
M10. Failure mode catalog — UC4-UC6 각각 3+ failure mode + system response
응답: Recommendation Specialist (A2) 의 9 failure mode + Integrator (A3) 의 5 추가 → 14 failure mode catalogued. 가장 위험: silent hallucination (verification PASS 인데 의도 다름) → forward fixture 강제 + multi-alternative + manifest immutability
M11. v2 artifact disposition — v2 = ground-truth example / migrated to generic+v2-extension / deleted post-generalization
응답: v2 artifact = 첫 plugin (generic+v2-extension). 27 idiom card → plugins/slab-design/registry/. 5 facade → plugins/slab-design/contracts/. 5 golden fixture → plugins/slab-design/golden/. v2 의 자산은 v2 plugin 의 1차 content 가 됨, 폐기 X

핵심 설계 요소 6가지

1. core/ + plugins/<system>/ 분리 (A1)

Mechanism (Synthesizer 2-layer, Contract Gate, Gap Surfacer, Twin Runner, Oracle Differ) 는 universal core. v2 specifics (79 slot, 5 facade, 9 JPA repo handling, Spring DI) 는 plugins/slab-design/. 새 system = 7 artifact + ontology import.

v2 자산의 운명: 27 카드 → plugins/slab-design/registry/, 5 facade → plugins/slab-design/contracts/, 5 fixture → plugins/slab-design/golden/. 폐기 없이 그대로 첫 plugin 의 content.

2. 5번째 Schema Layer ontology (A3 의 DDL)

기존 4-layer (Code/Domain/Mapping/Simulation) + Schema Layer (persistence surface). Additive migration — 기존 row 미수정, backout = drop new tables.

CREATE TABLE schema_tables (
  fqn, physical_name, label, domain, kind, is_lookup,
  storage_engine, source, confirmed, repo_id,
  revision_introduced INTEGER NOT NULL,
  revision_obsoleted INTEGER,
  PRIMARY KEY (fqn, repo_id)
);

CREATE TABLE schema_columns (
  id, table_fqn, physical_name, logical_name, sql_type,
  nullable, is_primary_key, pk_ordinal, default_value,
  repo_id, revision_introduced, revision_obsoleted,
  FOREIGN KEY (table_fqn, repo_id) REFERENCES schema_tables (fqn, repo_id)
);

CREATE TABLE schema_foreign_keys (...);
CREATE TABLE schema_indexes (...);
CREATE TABLE schema_constraints (...);

CREATE TABLE schema_code_map (   -- type_realizations 동형 (Section 2 UI 재사용)
  id, code_type_fqn, code_field_fqn,
  schema_table_fqn, schema_column_id,
  source, confidence, confirmed, confirmed_by,
  repo_id, revision_introduced, revision_obsoleted

Bitemporal (revision_introduced/obsoleted) — Verification 이 임의 historical revision 으로 replay 가능.

3. Recommendation Engine 4 방어 (A2)

  1. Typed tool: LLM 이 raw row 가 아닌 schema-validated JSON 받음 (hallucination 시 reject)
  2. Deterministic step jailing: parse/locate/gap/validate 는 결정론적, LLM 은 step 4 (compose) 안에서만
  3. Structured artifact output: Pydantic 강제, 위반 시 retry max 3
  4. Verification RPC fence: 모든 proposal → twin regen → regression + forward fixture

LLM context: FTS5 retrieval (top-N=20 + 2-hop) → 5-15K token. 5K+ class system 도 동일 mechanism.

4. Integrator (A3) — 단일 mutation point

모든 ontology mutation 이 Integrator 1개 channel 통과. Proposal lifecycle state machine:

draft → analyzing → ready → reviewed → accepted (target_revision 생성)
                                    └→ rejected (artifacts 보존, ontology 미반영)
                                    └→ stale (base_revision 가 obsolete)

Concurrent proposals: base_revision pin → first-apply wins, peers STALE_PROPOSAL.

5. Manifest 기반 reproducibility (A2)

proposals/<pid>/manifest.yaml:
  timestamp: 2026-05-13T...
  model_version: claude-opus-4-7
  prompt_hash: sha256:...
  ontology_revision: R_42
  seed: 12345
  retrieval_query_hash: sha256:...

동일 4-tuple 입력 → 동일 proposal id (캐싱). 100% reproducibility 는 LLM mutability 로 불가능, 동일 환경 reproducibility 만 claim.

6. 3 CI Gates (A3)

  1. Verification regression gate — PR 의 Java 변경 → twin regen + S1-S5 byte-identical 검증
  2. Schema-Code sync gate — Java @Column 변경 → schema_code_map migration 강제
  3. Proposal validation gate — PR 이 proposal_id 참조 시 artifacts_json.code_diff 와 PR diff 일치 확인

5. Worked example — "고객사 슬랩 두께 override" end-to-end (A2 + A3 통합)

#Actor / EngineOutputStorage
1 User → Recommendation spec.md ("고객사가 슬랩 두께 override...") proposals row, status=draft
2 Recommendation: Spec Parser + Ontology Locator JSON typed schema (entities/attributes/found_terms/found_actions/schema_layer) proposals/<pid>/spec.json
3 Gap Identifier (결정론적) 3 gap: column 부재 / action 분기 부재 / term 부재 proposals/<pid>/gaps.json
4 Schema Recommender (LLM jail) Option α (ALTER TABLE) + Option β (새 table), rationale + blast radius proposals/<pid>/schema.sql + schema-diff-rationale.md
5 Code Recommender (LLM jail) Java diff (SdThicknessAction.java L50 다음 새 block + 새 anchor) proposals/<pid>/code-diff.patch
6 Ontology Evolver (LLM jail) BusinessTerm + BusinessRule + AnchorBinding delta proposals/<pid>/ontology-delta.json
7 Proposal Validator → Verification RPC regression (S1-S5 unchanged ✓) + forward (S6 override=240 → thickness=240 PASS) verification_runs row + result_path
8 User Review (modeling UI) Option α 채택 + Sub-option decisions proposals.user_decisions_json
9 Integrator (transactional) ontology_revisions R_43 (parent R_42) + Schema Layer row + Domain delta ontology.db (single transaction)
10 Verification: full re-synth + regression run generated/<repo>/R_43/*.py + trace.json (all pass) content-addressed
11 Integrator: PR draft Schema migration SQL + Java diff PR + deep-link to modeling UI git branch + filesystem

각 step 의 artifact 가 (proposal_id, revision_id, run_id) stamp 보유 — 7분 후 Recommendation 이 같은 R_43 로 재조회 가능, race condition 차단.

Silent hallucination 잔존 Forward fixture 사용자 작성 강제 + multi-proposal + manifest 로 attack surface 축소. 완전 차단은 불가능
