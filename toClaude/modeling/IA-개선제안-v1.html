2. 사용자 멘탈 모델 — 「Workbench First」

제안 원칙 — Workbench 가 모든 작업의 기본 화면. 다른 탭은 (a) 입력 셋업, (b) 전체 조감, (c) 일괄 작업 의 3 역할만 가진다.

핵심 작업 흐름 (사용자 시각)

[ 입력 셋업 ] [ 핵심 작업 ] [ 전체 조감 / 일괄 ] Repository ─┐ 기준서 ├─→ Workbench (모든 메서드 단위 작업) ←─→ 온톨로지 그래프 매뉴얼 작성 ─┘ 용어 매핑 (배치) │ └→ L 트리: 메서드 검색 (역탐색 흡수) C 코드: anchor highlight C-R Ontology: 메서드 단위 매핑 + LLM 추천 R 패널: 룰 검토 (P17) | 영향 (P19→흡수) | 시뮬 (P22)

각 탭의 명확한 역할

역할탭언제 사용?
① 입력 셋업 (1회성 + 점진적) Repository / 기준서 / 매뉴얼 작성 새 코드/매뉴얼 추가 시
② 핵심 작업 (매일) Workbench 메서드별 매핑/룰 검토/영향 분석/시뮬레이션
③ 전체 조감 (검증) 온톨로지 그래프 관계 구조 점검, 누락된 governs 발견
④ 배치 작업 (특수) 용어 매핑 / 갭 큐 cold start, 정기 갭 검토

4. 적용 단계 (Phase)

단계변경의존난이도
Phase 1 (지금) 온톨로지 그래프 탭 추가, Workbench 가 default 임을 명확히 (이미 적용) P18 ✓ 완료
Phase 2 (P19 후) Workbench R 패널 「영향」 탭 활성화 (multi-layer impact). 영향 분석 탭 deprecation 안내 + 자동 redirect. P19 Multi-Layer ImpactPropagator 중
Phase 3 (P20 후) Workbench Command Palette (⌘K) 에 한국어 용어 검색 → 매서드 jump. 역탐색 탭 deprecate. 이미 P14 에서 ⌘K 일부 구현 저
Phase 4 (P22+ 후) 갭 큐 → Workbench R 패널 「갭」 탭. 전 저장소 갭 보기는 온톨로지 그래프 의 별도 모드로. P22 시뮬레이션 drawer 와 통합 검토 중
Phase 5 (선택) DI 그래프 → Repository 탭 우측 보조 패널. 기준서 + 매뉴얼 작성 통합. 없음 (UI rearrangement) 저

5. Workbench 가 핵심인 이유 (시연 시나리오)

실제 사용자가 「이 메서드 가 정말 이 도메인 룰 을 잘 구현했나?」 를 확인하는 흐름.
  1. L 패널 트리 — `feature.sd.process.std.service.CastSpecService.lookup()` 클릭
    • 「역탐색」 탭 없이 바로 메서드 도달
  2. C 패널 코드 — 메서드 source 표시. param/local/branch/literal 라인 색상 highlight
    • 실제 코드 가 ground truth (사용자 결정)
  3. C-R 패널 Ontology 카드 — anchor 4 개 → BusinessTerm 자동 추천 (alias 매칭 + LLM 보강)
    • 「용어 매핑」 탭의 메서드 단위 버전
  4. R 패널 「⚖️ 룰 검토」 (P17) — 메서드에서 추출된 BusinessRule 1 개 (lookup 종) 표시
    • 확정 / 편집 / 거부
  5. R 패널 「🧬 영향」 (P19 후 활성) — 이 메서드 변경 시 영향받는 다른 메서드/term/rule
    • 「영향 분석」 탭 흡수
  6. R 패널 「🔬 시뮬」 (P22~25 후) — Python 자동 생성 → Sandbox 실행 → 변경 전후 diff
    • 시뮬레이션 핵심
  7. 온톨로지 그래프 탭 으로 점프 — 이 메서드의 rule 이 그래프상 다른 term 과 어떻게 연결되는지 조감
    • macro 검증

6. 위험 / 트레이드오프

위험완화
역탐색/영향 분석 탭에 익숙한 사용자가 헷갈림 탭 deprecation 시 30 일 전환 기간 + redirect + 안내 toast
Workbench R 패널이 너무 많은 탭 (룰/영향/시뮬/참고/갭) 으로 비대화 각 탭 헤더에 도움말 + 탭 wrap 적용 (이미 P21b)
온톨로지 그래프가 100K+ 노드에서 느림 「관계 있는 노드만」 default ON + 페이지네이션 + 도메인 필터
DI 그래프 흡수 시 spring 전용 사용자 혼동 Repository 탭 우측 「인프라」 섹션 분리
