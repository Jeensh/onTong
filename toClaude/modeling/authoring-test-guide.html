"뭐 누른다고 되는게 없는데" 의 원인: 거의 확실히 ① 모드 토글을 안 누름 — 기본 진입 시 Detail 모드라서 Authoring UI 가 아예 표시 안 됨, 또는 ② Authoring 모드 안에서 첫 단계 (🆕 새 세션) 를 안 누른 채 다른 ① ~ ⑨ 버튼을 누름 — 모두 disabled 상태라 반응 없음.

🚀 추천 테스트 시나리오 (Round 5 재현, 한 entity 사이클)

1모드 진입
  • http://localhost:3000 접속
  • 상단 nav 의 Modeling 클릭
  • 우상단 mode toggle 의 ✏️ Authoring 클릭

→ 화면 중앙이 좌(채팅) + 우(preview) 분할로 바뀜.
→ toolbar 가 보이고 "🆕 새 세션" 만 활성화, 나머지는 회색 (disabled).

2세션 시작
  • toolbar 의 🆕 새 세션 클릭

→ 우측 "현재 세션" 카드에 UUID + cost $0.0000 표시.
→ 채팅에 "세션 시작 (id=…) — 코드 파일을 추출하면 인터뷰가 시작됩니다." 메시지.
→ "① 코드 추출" 버튼이 활성화됨.

3① 코드 추출 클릭 Sonnet · ~10s

HrSpecJpo.java 가 backend 로 전송됨. Sonnet 이 PK 4축 + 컬럼 4개를 구조화해서 반환.
→ 채팅에 HrSpecJpo → HR_SPEC, PK 4축 · 컬럼 4개 표시.
→ 우측 "현재 세션" cost 약 $0.02 로 갱신.

4② 가설 클릭 Opus · ~20s

Opus 가 도메인 entity 가설 + confidence + 우려 사항 생성.
→ 채팅에 "🧠 가설: 열연공장…" 표시.
→ 우측 "가설" 카드에 한국어 표시명 / 영어 식별자 / domain_role / confidence 표시.

5③ 인터뷰 클릭 Sonnet · ~15s

Sonnet 이 5~7개 한국어 질문 생성 (각 1줄 placeholder + my_guess).
→ 채팅에 "❓ 인터뷰 (N 질문)" + 질문 list 표시.
→ 하단에 답변 textarea 가 등장.

6답변 입력 + ④ 답변 흡수 Sonnet · ~10s

아래 텍스트를 textarea 에 붙여넣고 ⌘↵ (또는 Ctrl↵) 또는 ④ 답변 흡수 버튼:

공정계획에서 관리해.
와일드카드는 PK 에 *를 쓸 수도 있고 LIKE 패턴도 지원해.
기준값이 NULL 이면 자동 true 로 처리됨.
룩업 실패하면 후속 로직에서 NPE 가 발생할 거야 — 데이터 결함이지.
row 는 수십 정도. 공정계획팀 사용자가 갱신해.
그 외는 모름.

→ 채팅에 "📥 답변 정리됨 (5/6)" + 가설과 모순된 wildcard 자동 표시.

7⑤ 옵션 클릭 → 옵션 카드 클릭 Opus · ~30s

Opus 가 옵션 표 (보통 2~4개) 생성. 각 옵션 카드에 ASCII 구조도 + trade-off + 선택 버튼.
★ 추천 표시된 옵션 (보통 "Plant + Constraint Composition") 의 선택 버튼 클릭.

→ 자동으로 ⑦ 명명 capability 호출 (Sonnet, ~10s).
→ 우측 "엔티티" 카드에 한국어 라벨 + 영어 id + role 표시 (draft 상태).

8⑥ 갭 클릭 (선택) Opus · ~25s

Opus 가 코드 vs 도메인 갭 분석. 와일드카드 모순이 intent 갭으로 검출.
→ 채팅 + 우측 "갭" 카드에 갭 list (severity 색상).

9⑨ Archive 클릭 Sonnet · ~20s

Sonnet 이 archive markdown 자동 생성.
→ 우측 "Archive (markdown)" 카드에 전체 markdown preview.

10✓ Confirm 클릭 (최종)

엔티티가 ontology DB 에 영구 저장됨.
→ 우측 엔티티 카드의 draft 배지가 ✓ saved 로 변경.
→ 채팅에 "✅ N 개 entity 가 ontology DB 에 저장됨" + FQN 목록.
