F1. 세션 진행 누적 파일 (Round 5 패턴)

진단

우리 Round 5 협업의 본질: 각 step 의 결정이 round5-live-authoring.html 안에 archive 형태로 누적. 사용자가 언제든 어느 step 결정 다시 볼 수 있고, 다음 세션에서 이어가기 가능. "진행 중인 살아있는 문서" 가 핵심.

현재 product: 매 turn 결정은 authoring_decision_log DB 에 들어가지만 사용자가 보려면 API 호출이나 우측 preview 의 일부만 볼 수 있음. "진행 누적 HTML 문서" 가 없음.

F3. 프로세스 레벨 피드백 루프 (모든 단계 정정)

진단

사용자: "refresh 버튼을 좀 잘 모르겠는데, 프로세스에서 가설 뿐만이 아니라 모든 프로세스 레벨에서 다시 정정하면 다시 가설을 세우고 하는 피드백 루프 과정이 필요할 것 같은데, 지금은 그냥 가설에 리프레시 버튼 하나 있고 땡이야."

현재: 🔄 가설 다시 보기 버튼만. 그것도 답변(answer) 만 반영하지 다른 단계에서 정정 사항이 있어도 적용 안 됨. 전체 흐름의 어디서나 정정 → 영향받는 후속 단계 재실행 패턴 필요.

흐름 비교

현재 (단방향 + 가설만 refresh): extract → hypothesis → interview → answer → option → gap → naming → archive → confirm ↑ [refresh 가설] (답변 반영, 후속 다 cleared) Round 5 패턴 (모든 단계 정정 가능): extract → hypothesis → interview → answer → option → gap → naming → archive → confirm ↕ ↕ ↕ ↕ ↕ ↕ ↕ ↕ (각 단계 카드 옆에 "다시 / 수정" 버튼 + 사용자 코멘트 영역) → 사용자가 어느 단계에서든 "이게 잘못됐어, X 라고 정정" 하면 → 그 단계 + 후속 단계 모두 재실행 (또는 사용자가 선택)

옵션접근장단

사용자: "지금도 코드, 메뉴얼 등 보는 섹션이 필요없는데 칸을 차지하고 있는게 굉장히 불편해." → Authoring 모드 진입 시 좌측 LeftPanel + RightPanel 숨김 (또는 collapse). MainPanel 이 전체 너비 차지.

사용자가 토글 인지 못함. 헤더 전체를 클릭 가능 (✓ 이미 됨) 이지만 시각적 affordance 부족. ▾ 아이콘 더 크게 + hover 시 강조 + "클릭하여 접기" 안내 tooltip.
