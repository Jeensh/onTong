✏️ Authoring AI — 데모 따라하기 가이드

2026-05-05 · 체크박스로 진행 상태 저장 (localStorage). 새로고침해도 진행 유지. 한 cycle ~5분 / ~$1.
한 흐름의 큰 그림: 모드 진입 → 클래스 선택 → 세션 시작 → ① 코드 추출 → ② 가설 → ③ 인터뷰 → 답변 → ⑤ 옵션 → 옵션 선택 (자동 ⑦ 명명) → ⑥ 갭 → ⑨ Archive → ✓ Confirm. 중간에 ✏ 수정 / 🔄 다시 시험.

📋 Phase 0 — 시작 전 점검

0.1

두 서버 살아있는지

http://127.0.0.1:3000/ ← frontend / http://127.0.0.1:8001/api/authoring/sessions ← backend
둘 다 응답 OK 면 진행. 안 되면 사용자에게 보고하세요.
0.2

페이지 강제 새로고침

Cmd + Shift + R (Mac) — 모든 변경된 코드 hot-load
localhost:3000 의 캐시 비우고 최신 코드 적용

🆕 Phase B — 세션 시작 + 코드 추출 + 가설

B.1

🆕 새 세션 클릭

toolbar 의 🆕 새 세션 클릭
• 우측 "현재 세션" 카드: UUID + cost $0.0000 + operator default
• 채팅에 "세션 시작 (id=...)" 시스템 메시지
• banner 가 amber → emerald 로 변경: "✓ 선택됨: HrSpecJpo"
• ① 코드 추출 버튼 활성화 (회색 → 정상)
B.2

① 코드 추출 (HrSpecJpo) 클릭

toolbar 의 ① 코드 추출 (HrSpecJpo) 클릭. 약 10초 대기 (Sonnet)
• 채팅에 추출 결과 카드: HrSpecJpo → HR_SPEC, PK 4축 · 컬럼 4개
• cost 가 $0.02 정도 누적
• banner 가 사라짐 (jpo 추출 후 다음 단계 안내 자동)
B.3

② 가설 클릭

toolbar 의 ② 가설 클릭. 약 20-25초 대기 (Opus)
• 채팅에 가설 카드: 🧠 가설: 열연공장 표준? (Korean term + English id) + confidence 0.30~0.55
• 중요: "표준?" 같은 hedging (?) 또는 "추정" 표현 — humble prompt 적용 검증
• 우측 "가설" 카드 등장 — Korean 라벨, English id, role, confidence, PK 의미 요약
★ 평가 포인트 — 이전엔 "HrPlant" 같은 specific 이름을 처음부터 dump 했던 것이 R2-W1 P1-B 후 더 humble 해졌는지 확인

❓ Phase C — 인터뷰 (Q 별 textarea)

C.1

③ 인터뷰 클릭

toolbar 의 ③ 인터뷰 클릭. 약 15-20초 대기
• 채팅에 인터뷰 카드 + 5~7개 한국어 질문 list
• 각 질문 별로 별개 textarea + my_guess hint + skip 체크박스 + 옵션 select
• 마지막에 "추가 의견 (자유)" freeform textarea
• 하단에 "④ 답변 제출 (Q 별 정리)" 버튼
★ R2-W1 P3-A — Round 5 form 패턴 복원. 이전엔 단일 textarea 였음.
C.2

답변 입력 (Round 5 정답 시나리오)

각 textarea 에 한 줄씩 답변 (전체 한꺼번에 가능):
1. owner 또는 관리: 공정계획
2. wildcard: *를 쓸 수도 있고 LIKE 패턴도 지원
3. miss / 매칭 실패: NPE — 데이터 결함
4. row_size: 수십~백
5. maintenance: 공정계획 사용자
6. (그 외) 추가 의견: NULL PK 컬럼은 자동 true
제출 전엔 textarea 만 채워진 상태
C.3

④ 답변 제출 클릭

하단 ④ 답변 제출 (Q 별 정리) 버튼 클릭
• 채팅 사용자 메시지: 답변 transcript (• owner: 공정계획 ...)
• 채팅 assistant 메시지: 📥 답변 정리됨 카드
• 우측 가설 카드에 🔄 가설 다시 보기 버튼 새로 등장 (P2-B)
• cost 변동 X (frontend 가 직접 build, LLM 호출 안 함 — R2-W1 절감)

🎯 Phase D — 옵션 + ★ 피드백 루프 시도

D.1

⑤ 옵션 클릭

toolbar 의 ⑤ 옵션 클릭. 약 25-35초 대기 (Opus, 가장 큼)
• 채팅에 옵션 표 카드: 🎯 HrSpec 모델링 옵션 + 2~4개 옵션
• 각 옵션: name + 구조도 (ASCII) + trade-off 한 줄 + 선택 버튼
• ★ 표시 추천 옵션 (보통 emerald 강조 — Plant + Constraint Composition)
D.2

✨ F3 시도 #1: 옵션 카드의 ✏ 수정

옵션 카드 하단의 ✏ 수정 버튼 클릭. inline textarea 에 입력: 
이 옵션들이 다 비슷해 보여 — Plant 와 Spec 의 차이를 명확히 하고, 와일드카드 case 를 별도 옵션으로 추가해줘
그리고 ✏ 정정 후 재실행 클릭
• 채팅 사용자 메시지: "🔄 options 재실행 (코멘트: ...)"
• 약 25-35초 대기 (Opus 재호출)
• 새 옵션 표가 정정 코멘트 반영해서 다시 (와일드카드 case 강조 등)
• 우측의 채택 옵션 / 명명 / archive 가 cleared (cascading)
★ 이게 R2-W2 의 핵심 — Round 5 의 "사용자 정정 → AI 재검토" 흐름 복원
D.3

옵션 선택 (자동 ⑦ 명명)

★ 추천 옵션 (보통 Plant + Constraint Composition) 의 선택 버튼 클릭
• 채팅 사용자 메시지: "옵션 채택: 옵션 C — Plant + Constraint ..."
• 자동으로 ⑦ 명명 capability 호출 (Sonnet, ~10초)
• 채팅에 명명 카드: 🏷 명명 (2 entities) — 한국어 + English id (예: 열연공장 / HrPlant + 열연공장제약 / HrPlantConstraint)
• 우측 "엔티티" 카드 등장 — 각 entity 의 role / parent / 한국어 라벨
D.4

⑥ 갭 클릭 (선택)

toolbar 의 ⑥ 갭 클릭. 약 25-30초 대기 (Opus)
• 채팅에 갭 분석 카드: 🔍 갭 탐지 (N gaps, severity_summary)
• 와일드카드 모순이 intent 갭으로 검출 (사용자가 "*+LIKE" 라고 했는데 코드는 정확매칭만)
• 우측 "갭" 카드에 severity 별 색상 (high=rose, medium=amber, low=muted)

📦 Phase E — Archive + Confirm

E.1

⑨ Archive 클릭

toolbar 의 ⑨ Archive 클릭. 약 15-20초 대기
• 채팅에 archive 카드: 📦 Step 1 — 열연공장 entity 결정 ✓
• 우측 "Archive" 섹션이 새로 등장 — markdown 으로 렌더된 풍부한 글 (글자 잘 읽힘 — R2-W2-Now X1 fix)
• 우측 상단에 ⬇ .md 내려받기 버튼
E.2

⬇ .md 내려받기 (선택)

우측 Archive 섹션의 ⬇ .md 내려받기 클릭
파일 다운로드 — 파일명 예: step-1-열연공장-entity-결정.md
열어보면 markdown 으로 archive 내용
E.3

✓ Confirm 클릭 — entity 영구 저장

toolbar 의 ✓ Confirm 클릭 (emerald 색상)
• 채팅에 confirmed 카드: ✅ N 개 entity 가 ontology DB 에 저장됨
• FQN 목록 (예: term.smoke-slab.hrplant, term.smoke-slab.hrplantconstraint)
• 우측 "엔티티" 카드의 각 entity badge 가 draft → ✓ saved 로 변경
