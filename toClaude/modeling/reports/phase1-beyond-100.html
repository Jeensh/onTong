Phase 1 지식 동기화 — 100점을 넘는 16가지 방법 + 우리만의 차별화

2026-05-01 · 외부 프레임워크 100/100 너머의 진짜 압도적 시스템 청사진. 즉시 → 차별화 → 비전 → 문샷 4 단계 16 액션.
한 줄 결론
외부 프레임워크의 100점은 "CI 가 ontology 를 갱신하고 깨지면 build fail" — 결국 탐지+차단 수준이다. 진짜 압도적 솔루션은 "운영자가 모르는 사이에도 자가 치유 + 인과 추적 + 시간 여행 + 다른 시스템(DB/테스트/매뉴얼)까지 동기화 + 학습" 의 4 축으로 도약한다. 100점을 표준이라 가정할 때, 16가지 layer 를 모두 쌓으면 우리는 180점 영역까지 갈 수 있다.

🌟 우리만의 진짜 차별화 5가지 — 외부에 절대 없음

① 한국어 alias 기반 자가 치유
외부 솔루션은 영어 시맨틱만 가정. productTypeCd ↔ 품종코드 의 4-stage chain (exact/alias/embedding/LLM) 은 우리만의 자산. rematch 정확도가 외부보다 압도적으로 높을 수 있음 — 한국 제조 도메인 특화.
② 매뉴얼 ↔ 코드 양방향 sync
외부는 "운영자 입력 룰" 가정. 우리는 PDF/MD 매뉴얼 자동 인제스트 + auto_linker. 매뉴얼 fragment 변경 시 rule re-link 자동, 코드 변경 시 매뉴얼 references 자동 stale 추적 — 두 방향 모두.
③ LLM 영향 요약 (한국어)
"200건 binding break" 를 한국어로 "이 PR 은 품종 분류 체계 rename. 슬래브 사양 → 공정 매칭 단계까지 영향" 으로 요약. 외부의 영문 stack trace 와 차원이 다른 운영자 친화성.
④ 시뮬레이션과 결합한 binding 신뢰도
binding 이 실제 시뮬레이션 통과하면 confidence ↑, 실패하면 ↓. 외부는 "binding 이 살아있는가"만 봄. 우리는 "binding 이 시뮬레이션 ground truth 와 일치하는가"까지 검증. 유일무이.
⑤ 운영자 mental model 보존 — 변경 누적 시점에 도메인 카테고리 기준 알림
16번 dashboard 와 결합. "이번 sprint 에 「공정 매칭」 카테고리에서 binding 8건 stale 됐고, 모두 LLM auto-rematch 성공" 같은 도메인-aware 리포트. 단순 "binding 8건 깨짐" 이 아닌 "Slab 공정 매칭 영역에서" 라는 비즈니스 문맥. S6 도메인 맵 + S7 binding health 의 결합 효과.

🛣 권장 구현 시퀀스 — 4 주 로드맵

1주차
TIER 1 모두 (1, 2, 3, 4) — Watcher + Git provenance + Auto self-heal + Type-aware
목표: 75 → 100점. 외부 프레임워크 ideal 도달. 1~2일 작업 4건. 즉시 사용자 체감 ↑.
2주차
TIER 2 핵심 3개 (5, 6, 7) — Snapshot 버전닝 + DB schema sync + LLM 요약
목표: 100 → 124점. 우리만의 차별화 본격 시작. 시간 여행 + cross-system + 운영자 친화 한국어 요약.
3주차
TIER 2 보강 (8) + TIER 3 진입 (9, 10) — Test impact + Refactoring 분류 + Body embedding
목표: 124 → 147점. 정확도 폭발 단계. AST diff 분류 + embedding 등가성 = 자가 치유 적중률 90%+.
4주차
TIER 3 마무리 (11, 12) + TIER 4 진입 (14) — 패턴 학습 + WebSocket push + Auto-PR
목표: 147 → 168점. 자율 sync 영역 진입. 사용자가 "이게 이렇게 알아서 되네?" 체감하는 단계.
5주차+
TIER 4 확장 (13, 15, 16) — Bisect + Multi-repo + Drift Radar 대시보드
목표: 168 → 188점. 컴플라이언스 + 다중 모듈 운영 사이트 정식 release 가능 수준.

🎯 핵심 의사결정 포인트 — 1주차에 손대야 할 것

결정 이유 권고
file watcher daemon 가장 큰 사용자 체감 변화. 폴링/수동 → 즉시. 1일 작업. YES (1순위)
