curl 또는 Swagger 로 직접

📖 Swagger UI 열기 자동 생성된 OpenAPI docs — 모든 endpoint 시도 가능.

A
현재 BusinessTerm list
curl -s "http://localhost:8001/api/modeling/terms?repo_id=slab-design-real" | jq
B
매핑 제안 트리거
curl -s -X POST http://localhost:8001/api/modeling/terms/propose-bindings -H "Content-Type: application/json" -d '{"repo_id":"slab-design-real"}' | jq
기대: {"total_proposed": 9, ...}
C
매핑 후보 list (groupBy term)
curl -s "http://localhost:8001/api/modeling/bindings?repo_id=slab-design-real&status=proposed" | jq '[.items | group_by(.term_fqn)[] | {term:.[0].term_fqn, count:length}]'
D
신규 BusinessTerm 등록 (예: 강종코드)
curl -s -X POST http://localhost:8001/api/modeling/terms -H "Content-Type: application/json" -d '{"repo_id":"slab-design-real","qualified_name":"term.강종코드","canonical_label":"강종코드","aliases":["강종","grade","grade_cd"]}' | jq

⑥ 문제 발생 시

자주 마주치는 상황 + 해결
증상원인 / 해결
UI 에서 "BusinessTerm 조회 실패: TypeError: Failed to fetch" backend 가 죽음. ② 단계의 명령 다시 실행.
"매핑 제안 실행" 눌렀는데 0건 (1) BusinessTerm 시드 안 됨 — 좌측 list 에 0개. backend 재기동 필요.
(2) repo_id 가 "slab-design-real" 가 아닌 다른 값으로 변경됨.
404 — "repo_id 의 parse results 가 없음" backend startup 시 데모 repo 로딩 실패. tail /tmp/ontong_backend.log 로 slab-design-real load skipped 메시지 확인. 일반적으로 sample-repos/ 가 비어있거나 권한 문제.
frontend 컴파일 에러 (페이지 빈 화면) tail /tmp/ontong_frontend.log 확인. ManualOntologyBuilder / ManualUpload 사전 orphan 에러는 무관함.
같은 BusinessTerm 두 번 등록 idempotent — qualified_name 같으면 덮어씀. 안전.
UI 상에서 "확정" 눌렀는데 반영 안 됨 네트워크 탭에서 POST /confirm 응답 확인. 200 OK 이면 in-place 갱신, 실패 시 에러 strip 노출.
📋 로그 확인 명령
tail -f /tmp/ontong_backend.log /tmp/ontong_frontend.log
