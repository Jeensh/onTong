4 design 안 (모두 같은 시나리오)

V1 Three-pane (좌트리·중앙·우컨텍스트)

전통적인 IDE 레이아웃 · "안전한 선택"
좌측 트리 (Code/Domain/Action/Queue 탭 전환) + 중앙 detail 카드 + 우측 컨텍스트 (코드/매뉴얼/호출지점/영향 탭). 한 화면에 모든 정보. 익숙한 패턴.
3-pane 익숙 → 학습 곡선 낮음
컨텍스트 우측 패널이 풍부
action 탐색 위주 작업에 적합
정보 밀도 높음 → 5분만 봐도 피로
큐 작업 (반복) 에는 효율 X
▶ V1 열기

V2 Code-Domain Split (수평 분할)

매핑 자체가 first-class · "two worlds 가운데서"
좌 Code Tree | 우 Domain Tree | 가운데는 매핑 split (위 = Java body / 아래 = Action 카드). 코드와 도메인 동시 보면서 매핑. 코드 literal 클릭 → slot 매핑.
Code ↔ Domain 매핑이 시각적으로 자연
두 트리 동시 → 상호 참조 빠름
코드 본체에서 직접 anchor 클릭 → 매핑 흐름 직관
screen real estate 빡빡 (3 영역 + split)
큐 (Unmapped 등) 가 메인이 아님 — 별도 모달
▶ V2 열기

V3 Activity Feed (큐 우선)

"오늘 처리할 N 개" · "이메일 inbox 같은"
좌측 큐가 메인 (anchor / callsite / unmapped 통합 feed). 중앙 = 현재 작업 1개에 fully focus + AI 추천 + 후보 list. 우측 컨텍스트. 키보드 navigate 강조.
큐 처리 효율 ↑ (반복 작업 빠름)
AI 추천 + 컨텍스트가 메인 view 에 통합
키보드만으로 작업 가능
매뉴얼 + 영향 + 컨텍스트 한 자리
탐색 (Code/Domain tree 보기) 가 부수적 → 별도 탭
"바라보기 / 이해하기" 작업에는 부적합
▶ V3 열기

V4 Workspace Tabs (브라우저-like)

"Chrome 탭처럼" · 여러 작업 동시 진행
각 작업 = 1 탭. 한 탭은 fully focused single-task UI (정보 밀도 낮음). 탭 ⌘1-5 빠른 전환. 내용은 큰 글자 + 여백 충분 + 진척 큰 시각.
한 작업에 100% 집중 → 피로 적음
여러 작업 띄워놓고 빠르게 switch
핸드오프 / 멈췄다 다시 시작 자연 (탭 보존)
진척 ring 같은 시각이 큰 화면에 잘 어울림
탭 많아지면 관리 부담
컨텍스트 panel 없음 (메인 안에 흡수) → 동시 비교 X
▶ V4 열기
