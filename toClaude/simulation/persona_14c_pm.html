2. Suggestion 1-click — PM 가치 (이전 vs 이후)

이전: cand=0 → 회색 panel만 + "다시 시작" 안내. 사용자 좌절 → 영업/제조 PM 이탈.
이후: chip 보이고, 클릭 = reset + 새 start 자동 호출 (onSuggestionClick → reset() → start(suggestion, repo)). 손목 1번 동작.

판정: UX flow 자체는 ★★★★☆ — 보이고/누르면/돌아감. 다만 현재 추천된 chip 값(엣징그룹코드 / edgingGroupCd)이 ontology 에 매치 안 되어 다시 0 으로 떨어짐. 클릭은 했지만 같은 자리. 1-click "auto-research" UX 는 완성, "auto-resolve" 는 미완.

3. Hypothesis / Lookup 카드 렌더 fix — production-ready 여부

이전엔 frontend 가 kind="executed_hypothesis|lookup" 페이로드를 silently null 렌더 (빈 화면). 이번 GateExecutedReadOnlyCard 가 verdict + reasoning + evidence (hypothesis) / linked_term + callers + business_rules (lookup) 를 모두 surface.

S2/S3 payload 검증 통과 — 카드가 받을 데이터는 백엔드에서 정상. 판정: production-ready YES. PM 시연 가능 수준.

4. 회귀 우려 (2건)

  • R1 — suggestion chip 무한 루프 가능: chip 값이 candidate 검색 0 으로 떨어지면 같은 chip 이 또 추천된다 (S1 실측). 동일 query 가 N 회 반복되는 dead-end. 완화: chip 표시 시 "이미 시도한 항목" 제외 또는 chip 클릭 시 dictionary lookup 으로 별칭 확장.
  • R2 — confirm + respond 2-step 의존: locate/hypothesis turn 3 진입에 /confirm + /respond 두 호출 필요. frontend 자동 chain 정상 동작 확인됐지만 네트워크 끊김 시 turn 3 페이로드 유실 가능 (사용자가 reload 하면 turn 2 의 cand 만 보임). 완화: confirm 응답에 turn 3 가 함께 포함되는 단일 endpoint 검토.
