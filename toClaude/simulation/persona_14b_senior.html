실 fixture 실행 (full scope) 와의 gap

  • 측정하는 것: "이 hypothesis 가 fixture 로 동작 가능한가" 의 name+type compat 만. 실제 method 호출, 실제 입력 주입, 실제 분기 trace, 실제 throw 캡처는 0.
  • 못 잡는 false-positive: param name/type 은 맞지만 actual 분기 미실행 (e.g. order 가 null 이면 NPE — body 가 정말 그렇게 던지는지 검증 X).
  • 못 잡는 false-negative: var 가 param 명과 다른 이름 (Korean ↔ English, alias, nested field 접근) → S1 같은 강등 회귀.
  • 판정: acceptable but not enough. fixture readiness 의 1단계 (name compat) 만 가드. 실 실행이 들어와야 verdict='yes' 가 진짜 yes 가 된다.

다음 Phase 우선순위

  1. 14B 보강 (precision) — Korean↔English var-alias 보강 (term.aliases / ontology lookup) 으로 S1 회귀 차단. 1-day. 가장 cheap.
  2. 14F anchor_bindings — var → AST anchor 직접 결합. compat 체크가 substring 이 아닌 binding 기반이 되면 정확도 도약.
  3. 실 fixture invoke — 가치 최고지만 multi-day. param synthesis + sandbox 안정화 + result 해석 모두 필요. 14F 이후가 정석.
