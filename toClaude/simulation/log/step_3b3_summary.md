## 주요 결정

- **`PythonGenerator()` 생성자 인자 없음** — spec 05 §1.2 는 ontology_client 를 받는 형태지만, echo-stub 첫 iter 는 dispatch tree 자체가 RunPlan 에 들어있으므로 ontology lookup 불필요. 후속 iter 에서 (loop iterable derive / atomic_override resolve) ontology_client 추가 시 inject.
- **loop / optional 무시** — `is_in_loop` / `optional` 플래그 가 있어도 그냥 sequential dispatch. 후속 step (3b-4 orchestrator 가 loop iterable derive + condition eval 책임) 에서 보강.
- **atomic_overrides 적용 미구현** — 헤더 docstring 에 echo 만. 실제 patching 은 spec 04 §1.2 의 4-rule algorithm (orchestrator 책임).
- **import 화이트리스트 — 1개만** — 본 step 의 echo-stub 은 DelegationTraceFrame 만 사용. 후속 iter 에서 `RunInputs` / lookup helper 등 추가 시 화이트리스트 확장.
- **run() 시그니처** — `(inputs, java_sandbox, lookup_source, run_options)`. spec 05 §1.3 step 4c 와 §4.5 orchestrator entry 의 묶음.
- **dedup 보존 순서** — 같은 action_fqn 이 두 번 나와도 dedup 하되 첫 등장 순 유지 (java_dispatch_calls 사전 검증 용).
