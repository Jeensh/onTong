결론

  • ontology 의 83 terms · 136 actions · 148 realizations · 163 anchors · 22 rules 모두 시뮬에이전트의 endpoint 와 결과 surface 에서 실제로 활용됨.
  • hypothesis_workflow 의 baseline 은 Java :8080 의 21-step 실제 알고리즘 결과 (golden S1 byte-equal). projection 은 productivity 비율 모델.
  • impact 의 _target_change 는 seed 의 before value 직접 조회. _affected_orders 는 PRODUCT_CD 매칭으로 5건 surface.
  • 모든 detected_terms 는 business_terms.label/aliases_json LIKE 매칭 결과.
  • SSE 스트리밍이 4-stage 순차 progressive UX 제공.

알려진 한계 (후속 작업)

  • _affected_steps 가 indirect call 까지는 추적 못 함 (caller_graph 가 SimV2 mock 이라 1-hop 한계).
  • affected_actions 는 declared_on_term 매칭만 — actions 의 inputs/outputs 분석은 미구현.
  • ontology API 정식 endpoint /api/ontology/* 가 modeling 서버에서 나오면 mock 의존성 제거 가능.
