3. 김PM 시점 평가

전체 판정: Yes — 이전보다 도움이 된다.
이유: (1) 풀 문장이 사라져 검색 정확도 향상 가능성 확보, (2) Q1 처럼 어휘 미스매치일 때 "이렇게 부르세요" 가이드가 나옴 (이전엔 빈 화면), (3) Q3 같은 명확 질문은 top-1 매칭이 의도와 일치 (SdOrderValidator).

4. 남아있는 마찰 (구체)

  1. Q2 "두께 검증" → top-1 이 SdOrderValidator.validate (general validator). 김PM 은 "두께만 검증" 메서드를 기대 — 예: checkOrderSize, SdThicknessAction. 키워드 "검증"이 광범위해 두께-특화 메서드가 후순위로 밀린 가능성. 즉 search_terms 가 추출돼도 도메인 중요도 가중치가 두께를 못 끌어올림.
  2. Q1 "엣징 마진" candidates 0. suggestions 가 surface 됐지만 그 다음 단계 (사용자가 "엣징그룹코드"로 다시 묻기) 가 1-click 이 아님. UI/API 에서 suggestion 클릭 → 자동 재검색이 없음.
  3. "엣징 마진" suggestion 에 한국어 + 영어 (camelCase) 가 둘 다 나옴. 김PM 은 코드를 못 읽으니 edgingGroupCd 는 노이즈. 비즈니스 용어 1 개만 노출하는 게 친절.
  4. business_rule sources 5 개 (DG001~DG005) 가 항상 같이 surface. Q2/Q3 응답에 두께/엣징 무관한 재고주문/포장단중 rule 까지 붙어옴. 김PM 시점 "관련 없는 정보 노이즈" 로 보일 위험.

5. 추가 개선 우선순위 추천

  1. 도메인 중요도 가중치 추가 (Q2 마찰): search_terms 중 "두께"가 BusinessTerm 이면 ranking boost. 일반 validator 보다 ThicknessAction 류 상위. 이미 Phase 12 에서 _apply_ranking_boost 패턴 있으므로 search_terms × declared_on_term 매칭 추가.
  2. suggestion 클릭 → 자동 turn 진행 (Q1 마찰): 프론트엔드에서 suggestion 칩 클릭 시 새 message 로 자동 /respond 발사. 김PM 이 키보드 안 잡아도 됨.
  3. business_rule sources 의 query 관련성 필터: Q2/Q3 응답의 DG001~DG005 가 모든 응답에 dump 되는 게 아니라 search_terms 와 entity 매칭되는 rule 만 surface (예: 두께 → ThicknessAction 의 declared_on_term 과 연결된 rule).
