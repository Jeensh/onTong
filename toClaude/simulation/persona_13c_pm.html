4. 흥미로운 발견

  1. conditions 가 backend 까지 흘러감 but body_signals=0. Q2 sources 에 body_signals=0 rule_signals=4 명시 — 즉 LLM 이 추출한 conditions 를 body text 와 매칭하는 단계가 아직 없음. 룰북에만 의존. body 내 "qty == 0" 같은 분기 자동 탐지가 들어가면 confidence 가 0.75 → 0.95 도약 가능.
  2. "엣징 마진" 데이터 갭 = Phase 13b 와 동일 위치. ranking boost 가 안 작동하는 게 아니라 해당 BusinessTerm 자체가 modeling 시드에 없음. suggestions 가 "엣징그룹코드" 로 안내해도 PM 이 다시 타이핑해야 — 1-click 재검색이 여전히 없음 (Phase 13b 미해결 마찰 #2 그대로).

5. Phase 14 우선순위 추천

  1. suggestions chip → 1-click 자동 재검색 (Phase 13b 부터 미해결): 프론트엔드 chip 클릭 → 새 turn 자동 발사. Q1/Q3 같은 어휘 미스매치 시나리오의 차단을 해소. 백엔드 변경 0, 프론트 hook 만.
  2. conditions × body text 매칭: build_gate_hypothesis 내부에서 추출된 conditions 의 var 토큰(예: "qty", "수량") 을 body_text 와 substring 매칭 + 분기문(if/</>) 패턴 매칭. body_signals > 0 이면 confidence 0.75 → 0.9 boost + reasoning 에 "body L23: if (qty <= 0) return fail" 같은 인용 추가. PM 시점 "여기에 처리됨" 답이 더 구체적.
  3. candidates 0 일 때 suggestions 자동 expansion: 현재 suggestions 가 surface 만 됨. backend 가 suggestions[0] 으로 검색 1회 더 시도해서 candidates 채우는 fallback. PM 의 재타이핑 부담 제거.
