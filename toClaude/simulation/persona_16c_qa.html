평가

통과 — 16C 는 QA 입장에서 명확히 가치 있음. 정상 5/5 false-positive 0, 모순 케이스 (S+) 정확히 W1b surface, "확실한 근거" Q5 비전을 한 단계 더 충족.

W1~W3 정의 합리성

  • W1 (no_rule): body_unsupported + rule=0 → 합리. verdict 가 fixture 만으로 yes 라면 발화 필요. 실측 미발화 (현 verdict 알고리즘이 verdict=unknown 으로 떨어뜨림 — 안전).
  • W1b (rule_only): body_unsupported + rule≥1 → 실제 발화 확인 (S+). 의도된 fallback 을 명시적으로 사용자에게 알리는 핵심 패턴. 유지 권장.
  • W2 (no_strong_evidence): compat=fail + rule=0 + body<2 → 현재 verdict 알고리즘이 이 조합을 verdict=unknown 또는 likely_no 로 강등하므로 거의 발화 안 함. 안전망 역할 OK.
  • W3 (cross_evidence_mismatch): likely_no/no + compat=ok + body≥3 → 합리. 실측 발화 없음 (조건 강함). 회귀 catcher 로 유지 가치 있음.

추가 권장

  • W1c 신설: verdict=yes/likely_yes + matched_var=='' (alias 한·영 갭) + rule≥2 → body_unsupported_alias_gap. S+ 케이스가 정확히 이 분류 — "rule_only" 보다 root cause 더 명확 (alias 사전 보강 필요).
  • W4 후보: target action 이 *Test / Mock* 클래스 → integrity_warning=target_is_test (S4 잡힘). ranking 단계가 본질이지만 surface 까지 도와줌.
  • UI surface: 현재 sources[] detail 문자열에 묻혀 있음. EvidenceCard 에 빨간 배지로 별도 노출 권장 (사용자 가독성).
