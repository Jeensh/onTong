OQ-1 · 인바운드 패치 권한 정책

A 가 X 를 rename 할 때 X 를 인용하는 inbound 문서들을 시스템이 자동 패치한다. 이때 권한은?

A 가 inbound 문서 자체에 write 권한이 없을 수 있음. 정책 결정 필요.

OQ-2 · 스냅샷 보존

스냅샷 보존 정책

100K × 평균 20KB × N = 디스크. N=20 가정 시 약 40GB.

OQ-3 · Elasticsearch 도입 시점

ES 를 언제 도입?

사용자가 보조1 에서 ES 도입 가능 체크. 도입 타이밍 + 한국어 nori 검증 시점.

OQ-4 · ChromaDB chunk 본문 안 path 처리

L5 — chunk 본문에 박힌 path prefix ([분류: ...] [문서: ...]) 를 rename 시 어떻게?

현재 _build_path_prefix 가 chunk 본문에 path 를 prepend (RAG 정확도 향상 목적). rename 시 이걸 어떻게 다룰지 비용 큰 결정.

OQ-5 · Bulk 동시 작업 제한

drag-and-drop 다중 선택 + 폴더 rename 등 bulk 작업의 동시 사용자 한도

OQ-6 · 멀티호스트 ContentStore 매체

멀티 호스트 / enterprise profile 에서 마크다운 파일 자체를 어디에 저장?

현재는 LocalFS. 멀티 호스트 시 atomic rename() 보장 필요.

OQ-7 · Profile 토글 hot-reload

Profile / 백엔드 토글이 재시작 필요? 아니면 hot-reload?
